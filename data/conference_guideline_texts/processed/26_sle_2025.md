1. **Availability**: Artifact must be hosted in a permanent archival repository (e.g., Zenodo, FigShare, OSF) with a DOI; DOI must point to the exact version evaluated by the AEC.
2. **Evaluation Process**: Two-phase review:
3. **Kick-the-Tires**: Integrity and setup check; authors have 5 days to address issues via interactive HotCRP discussions.
4. **Artifact Assessment**: Detailed evaluation of whether the artifact supports the claims in the paper.
5. **Functionality**: Artifact must be consistent with the paper, runnable without errors, and include minimal setup steps. Push-button execution (single script) is strongly encouraged.
6. **Reusability**: Clear documentation, code organization, and mapping of outputs to paper sections/figures/tables; use of widely supported open formats (CSV, JSON) recommended.
7. **Completeness**: Must include all necessary components; reduced input set required if full experiments take days to run.
8. **Documentation**: Markdown overview using official template, explaining artifact structure, setup, usage, and link between outputs and paper content.
9. **Executable Environment**: Docker image strongly recommended; VM in OVF/OVA format acceptable; no internet downloads during evaluation; avoid closed-source dependencies.
10. **Hardware Requirements**: If special hardware is needed, authors must notify AEC chairs in advance and provide access (e.g., SSH to hosted platform).
11. **Submission Package**: Must include DOI link, PDF of accepted paper, and Markdown overview file; exactly one artifact per paper.
12. **Version Control**: Evaluated artifact must match the version linked in the paper; updates after evaluation not permitted without new DOI.
